What the log shows:
- The watchdog names the hung task (T1_sensor) about 10.3 s after the hang (16140 ms -> 26460 ms), resets the chip, and the
  reason is reported after the restart. Repeated three times with the same result.
- The backtrace shows IDLE or T2_uart because it is the stack of the CPU that handled the timeout; the hung T1 is blocked on a
  semaphore, so it is not running on any CPU. The culprit is the task list line, not the backtrace.
- The long press was triggered by a short tap in these runs: the button module of this build reads low at rest and high when
  pressed, and the code still assumed the opposite (pressed = low). The button events in these runs were therefore inverted.
  This was fixed afterwards with config::BUTTON_PRESSED_LEVEL.
