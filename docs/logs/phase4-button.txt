Phase 4.2 button gestures log (ESP32-S3-DevKitM-1, ESP-IDF 5.5.3)
The button is a 3-pin module (VCC, GND, OUT) with an on-board pull-down: OUT is low at rest and high while pressed
(config::BUTTON_PRESSED_LEVEL = 1). Short press: clear the error counter. Long press (3 s): watchdog test.
Captured with: pio device monitor (COM4, 115200 8-N-1).

Notes:
- Four presses give four "error counter cleared" lines.
- The first press was shorter than the 50 ms debounce quiet time, so its release event was filtered out. The long-press
  timer then checked the pin after 3 s, found the button released and counted a short press. This fallback works but
  reacts 3 s late for such very short taps (known limitation).
- ERR was already 0 in this test, so it shows the gesture, not a non-zero counter being reset (that is covered by the
  ErrorCounter unit test).

Notes:
- The long press fires exactly 3000 ms after the press while the button is still held.
- The release that follows is ignored: the gesture was already handled.
- The watchdog names T1_sensor about 10.2 s after the hang (75230 ms -> 85460 ms) and resets the chip.

Note on log levels: this log was captured with an earlier firmware build in which the button lines ("press event", "release event", "long-press timer after ...") were printed at INFO level. In the current code they are `ESP_LOGD`, and the default log level is INFO, so a fresh build does not print them. The behaviour is the same; set the log level to DEBUG (or change `ESP_LOGD` to `ESP_LOGI` in `src/reliability/supervisor_task.cpp`) to see them again.
